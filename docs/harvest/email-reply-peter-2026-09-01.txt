B. Custom RankExpression

Today, one browser request to Parigo’s /api/search causes the BFF to run two Harvest cloudsearch calls in parallel: a title-only query, followed by an aggregate editorial result set from which those literal titles are excluded. Track results are then enriched through gettracks. Autocomplete applies the same title/aggregate strategy to both Track and Album results.

The extra title lane is currently necessary. With the default Harvest ranking, literal titles can appear too far down the aggregate response; for example, the exact album MUSIC ON HOLD was absent from the first 30 aggregate results, while our title-first merge places it first.

If a Parigo RankExpression can reproduce that priority inside a single aggregate query, we should be able to remove one cloudsearch call from each Track or Album search while keeping the BFF and the required enrichment calls.

Our initial business-weight proposal is:

Track view
- exact TrackDisplayTitle: +100
- full phrase in TrackDisplayTitle: +70
- all query terms in TrackDisplayTitle: +50
- Track keywords, mood, music-for, category or genre: +25
- Track description: +15
- AlbumDisplayTitle: +12
- Album keywords or description: +8
- composer or library: +5

Album view
- exact AlbumDisplayTitle: +100
- exact catalogue reference: +80, if that field can be enabled safely
- full phrase in AlbumDisplayTitle: +70
- all query terms in AlbumDisplayTitle: +50
- Album keywords: +25
- Album description: +15
- contained TrackDisplayTitle: +10
- Track editorial metadata: +6

For recency, we would use it only as a tie-breaker: at most +5 for releases from the last 30 days and +2 for days 31–90. We would not want a recent weak match to outrank an older, clearly relevant title.

This is our first proposal, so we would very much appreciate your view on the weighting. Would separate Track and Album profiles be possible, and could the same ranking be used for cloudsearch and autocomplete? At this stage, an indication of feasibility, likely setup cost and whether reindexing would be required would be very helpful.
